CS231N Phys4D — TA feedback brief (current status)
==================================================


1) High-level pitch (30 seconds)
--------------------------------
We simulate a calibrated multi-camera sphere–ground bounce in PyBullet, export
multi-view RGB (and masks, poses). We train off-the-shelf 3DGS (single time
slice) and fudan 4D Gaussian Splatting on the full video so we have a dynamic
radiance substrate. Separately we build tooling to link Gaussians to rigid
object motion and to quantify physics-related metrics (restitution splits).
Longer-term claim (see docs/project_claim.md): inverse identification of a
physical parameter from video-style observations, extrapolation past training
frames, and counterfactual edits — with M2 stressing a controlled simulator
first.


2) What is implemented today (facts)
-----------------------------------
Simulator & data (local)
  - PyBullet rollout: RGB, segmentation masks, cameras.json,
    object_poses.csv, metadata.
  - Config-driven train/test splits on cameras and frames.

Vision packaging
  - Static 3DGS folder (Blender/transforms JSON) + Modal job training
    graphdeco-inria/gaussian-splatting on one timestep.
  - Full-bounce DyNeRF-style folder for fudan 4DGS (transforms_train/test,
    per-frame "time"), export script + Modal upload/train/eval paths.

Stock Gaussian training on our data
  - Vanilla 3DGS and vanilla fudan 4DGS; we did not fork their optimization
    cores for Milestone-style experiments yet.

Visualization & measurement
  - Raster renders of the 4D checkpoint at dataset cameras and times → PNG stack
    + MP4 (H.264 when ffmpeg exists) for qualitative review vs raw sim frames.
  - Optional orbital camera path preview (constructed geometry, novel views).
  - Script for PSNR/MAE-style metrics vs ground-truth PNGs on train/test splits.

Pose / object linkage (early integration)
  - Load Gaussian PLY, rigid warp using object_pose trajectory (relative motion
    to handle world/frame offsets), sphere selection helpers, mask projection
    scripts for qualitative alignment checks.

Physics scaffolding
  - Toy differentiable vertical bounce + synthetic restitution recovery tests.
  - Trajectory-split script: fit restitution on train-frame subset, report
    error on held-out test frames using pose-derived heights (sanity baseline).

Infrastructure
  - Modal app: upload/train 3D and 4D, export SuperSplat-oriented PLY,
    render trajectory, orbit, remote metrics.


3) Honest positioning (avoid overselling)
-----------------------------------------
  - Strong: reproducible simulator data, calibrated multi-view temporal export,
    end-to-end 4DGS training + rendered videos + quantitative image metrics tools.
  - Vanilla: the 4DGS/3DGS training code itself is upstream; novelty is how we
    package data, tie to physics hypotheses, and build toward jointly constrained
    models—not “new splat rasterizer”.


4) Where we intend to innovate / contribute something new
---------------------------------------------------------
Roadmap-aligned ideas (consistent with docs/project_claim.md):

  A. Inverse physics + appearance
     Estimate interpretable parameters (starting with restitution) from signals
     that move toward pixel/full render loss, not only pose columns.

  B. Extrapolation & evaluation
     Show predictive gain on held-out time/cameras when physics constraints or
     object-linked Gaussians are used versus pure 4DGS free fit.

  C. Counterfactual / editable physics
     After identification, edit parameters and synthesize rollout or render
     (e.g., “stiffer bounce”) as a demos hook.

  D. Object-centric Gaussian scene
     Tight coupling between masks/poses and a compact object Gaussian set (warp,
     segmentation, eventual joint optimization)—useful narrative vs scene-wide
     agnostic dynamics.

Concrete “novel enough for class” deltas if we execute them:
  - Explicit train/test splits in sim + quantitative reports tying 4DGS error
    to physics baselines on the SAME episode.
  - Pose-linked Gaussian warp + diagnostics (coverage, drift) bridging sim
    truth and splat coords.
  - First integrated pipeline from PyBullet episode → Modal 4DGS → calibrated
    render QC + numeric metrics.


5) Known gaps / risks (good TA talking points)
-----------------------------------------------
  - Projection / warp alignment vs masks still brittle (axis & FOV matching).
  - Restitution today is partly pose-based; differentiable raster loss not yet
    the main estimator.
  - Interactive 4D viewers are limited; offline MP4 is the pragmatic QC path.
  - Large checkpoints stay out of git; reproducibility hinges on scripted export
    + Modal retrain.
